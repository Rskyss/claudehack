# ClaudeHack 完整检查报告

检查日期：2026-11-01。对象：仓库 v0.1.1、扩展 v2.3.0，以及对应本机部署。检查性质：代码审阅、离线复现、本机只读状态核对；未部署修复。

## 结论

当前本地服务正在运行，但存在已经复现的兼容性和协议处理缺陷，不能认定为“完全干净”“全面隔离”或“不会再要求验证”的环境。最应优先处理的是护盾扩展对原生浏览器功能的广泛改写，其次是代理协议、CLI 出口预检和系统代理恢复的边界问题。

没有证据证明这些缺陷触发了本次 CAPTCHA 或身份核验，也没有银行卡问题的证据。此前直接使用 VPN 不出现、切换配置后反复出现，是值得追查的前后差异；账号、会话、出口和扩展没有经过同条件对照，不能据此锁定其中一个原因。

当前三个本地服务和 root 守护程序均运行，系统 PAC 已开启，受保护执行路径权限正常。无需为了排查反复尝试登录、付款或清空 Cookie。

覆盖扩展四个代码/规则文件、HTTP 网关、SOCKS 分流、PAC 与 PAC 服务、三个 CLI 包装器、macOS 守护程序及四份服务模板、安装文档、开发记录、Git 钩子、现有测试和静态图片资产。核对本机服务、监听地址、系统代理状态、部署文件差异、权限，以及两个相关 Chrome 配置的有限偏好和扩展安装记录。

没有读取真实代理凭据内容、Cookie 内容或日志内容；没有访问 Claude、验证码、支付或身份验证页面；没有清理浏览器数据或修改运行配置。未做整机恶意软件取证、全部 Git 历史秘密审计、上游信誉调查或外网连通性复测。

证据分为四层：

1. **原生离线对照**：Node 的真实 Date/Intl，在未注入和注入真实扩展脚本后比较行为。
2. **边界替身测试**：Canvas、字体、语音、RTC、Worker 使用替身，验证脚本如何修改输入/结果；不代表真实 Chrome 渲染或音视频测试。
3. **本地协议复现**：模拟上游、Unix socketpair、离线 PAC 求值和无监听回环端口；无真实账号或外网请求。
4. **本机状态检查**：实际文件权限、launchd、监听端口、系统 PAC；配置文件中的设置不等同于全部浏览器运行行为已经实测。

## 扩展的功能影响与承诺边界

以下行为是代码主动实现的功能，不能一概称为意外 bug；但它们意味着“日常办公零影响”的承诺没有依据：

- Canvas 字体设置会删掉匹配的中文字体；字体可用性查询会对这些字体强制返回 false。替身中 `16px "PingFang SC", Arial` 被改成 `16px Arial`。没有实测具体网页的像素变化。
- 当语音列表还存在其他选项时，中文语音会被过滤，可能影响页面的正常语音选择。
- RTCPeerConnection 包装器清空调用者的全部 ICE 服务器配置，可能影响依赖 STUN/TURN 的音视频连接；未进行真实通话测试。
- 扩展在匹配页面的 MAIN 环境、document_start 和多个 frame 中运行，范围包含 Google、Stripe、Persona、hCaptcha 等，不只 Claude。
- 后台 WebRTC 策略作用于整个 Chrome 配置文件；当前机器还有同类管理策略。因此停用扩展不等于恢复所有网络/隐私设置。
- Worker 回退只捕获同步异常，没有处理异步加载或执行失败，不能保证“平滑回退、零报错”。没有实测某个真实 Chrome CSP 页面失败。
- 多处空 catch 使失败静默，且后台没有确认 WebRTC 策略设置是否成功。页面不报错不能证明全部调整已生效。

四个扩展代码/规则文件中没有发现读取 Cookie、收集证件或外传数据的实现。这只是文件范围内的检查结果，不构成整机安全认证。

## 部署、隐私与安装问题

**运行日志权限需要收紧。** 普通日志为 0644，相关父目录为 0755，检查到的 ACL 没有阻止其他本机用户读取。源码会记录访问域名，普通 HTTP 路径还会记录完整 URL，查询参数可能包含敏感信息。此次未读取日志内容，不能断言日志已经包含凭据。root 守护日志另为 0600，真实代理配置也为 0600。

**独立窗口不等于独立网络环境。** 两个已查 Chrome 配置都引用同一份解压扩展目录；机器级 PAC/WebRTC 策略共同作用。Local State 最近使用配置记录为 Default，而此前检查过的独立配置为 Profile 31；这个记录不是当前前台窗口的确认，但说明不能直接沿用上一窗口的结论。未发现所检查 Cookie 例外条目中存在会话结束清除规则；未读取 Cookie 内容，无法证明没有旧 Cookie。

**上游认证传输依赖部署网络。** 网关使用普通 TCP 向 HTTP 上游发送 Basic 代理认证，代码本身没有为这一段建立 TLS；目标网站 HTTPS 不等于代理认证这段也受 TLS 保护。是否另受 VPN 加密依赖实际网络路径，本次未抓包，不能宣称凭据已在公网泄露。

**README 安装仍有操作缺口。** 插件 ZIP 加载步骤准确，且已明确没有一键安装器；但完整环境部分只提供 PAC 策略字段、替换服务模板、编译和启用的文字要求，缺少非开发者能逐步执行的策略应用、服务启用及生效验证流程。CLI 的“全局锁定”“消除遥测信号”等源码注释，也强于一次预检和环境变量所能保证的范围。

## 已知限制与未确认疑点

- 本地代理采用每连接线程，没有总连接数上限；阻塞 sendall 不受 select 的空闲超时完全约束。没有压测，不能断言实际资源耗尽。
- SOCKS 某些异常路径依赖对象回收关闭连接。真实 socketpair 检查在释放引用并回收后 FD 关闭，未复现持续 FD 泄漏，只列为清理确定性不足。
- PAC 服务对任意 GET 返回固定 PAC，没有任意文件路径拼接；PAC 文件缺失等异常未提供明确错误处理。
- CLI 包装器不是操作系统网络沙箱；绕过包装器启动、忽略代理变量的子进程，以及明确配置的 NO_PROXY 例外，都不受“全部隔离”的保证。
- 上次 AGY 的一次受限运行测试不能推广为 AGY 默认永久隔离；本次没有执行 AGY 或 Claude 模型请求。
- IP 的商业标签、第三方评分、Cookie 新旧、验证码出现次数，都不能直接揭示平台内部判定。未验证银行卡拒付、3DS 或支付交易状态。
- 新增第三方域名、浏览器真实请求链、IPv6/DNS/WebRTC 的实际联网行为、本次当前出口和上游健康度不在这次离线复现的覆盖范围。

## 建议修复顺序与验收

1. **先收敛扩展干扰。** 以恢复原生日期、Intl、字体和语音等正常功能为目标，重新明确是否需要保留每项修改；不要继续增加伪装。保留已经正常的网络入口，避免把功能修复和换 IP 混在一起。
2. **补齐代理与预检正确性。** 为 F04–F08 加入失败回归，再修复 HTTP 复用、完整状态解析、域名规范化、守护开关检测与 CLI 预检路径；分别验证正常和异常情况。
3. **收紧日志与修正文案。** 处理文件权限、URL 查询参数记录和日志保留；明确配置范围，补齐安装/恢复步骤。未经明确范围确认不清除历史浏览器资料或日志。
4. **最后做一次受控的人工对照。** 离线回归和必要的浏览器本地测试通过后，在固定账号、配置和出口条件下，由用户完成正常验证；一次只改变一个因素。验证码不出现不是身份核验已解除，网络检查通过也不是支付成功。

修复验收应基于功能恢复、协议正确性和失败行为，不应以“保证免 CAPTCHA/KYC”为标准。
